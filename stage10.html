STAGE 10

覚える回路とCPU

クロック・レジスタ・1サイクル
🎯 ミッション
回路が値を覚えるしくみと、CPU が命令を1つずつこなす「取り出し→解読→実行」を説明できるようになろう。小さな CPU で2つのプログラムを最後まで動かし、確認クイズに全問正解すれば合格。
未達成
ねこ博士
最後のステージだ。ここまで作ってきた回路には、共通の弱点がある。足し算回路の入力を変えたら、答えはどうなる？
うさ美
すぐに新しい入力の答えに変わります。前の答えは消えてしまう。
ねこ博士
そう。出力がそのときの入力だけで決まる回路を組み合わせ回路と呼ぶ。でも CPU は、計算した答えを覚えておいて、次の計算に使いたい。今日は「覚える回路」を作る。手がかりは、STAGE2 の最後にきみが言ったことだ。
うさ美
NOT を2回通すと元に戻る、ですか？
ねこ博士
そう。では、NOT を2つつないだ出口を、最初の NOT の入口に戻して輪にしたら、どうなると思う？
うさ美
1つ目の NOT の入口が 1 なら、出口は 0。2つ目の NOT で 1 に戻って、それがまた1つ目の入口へ……ずっと 1 のまま回り続けます。0 から始めても、ずっと 0。輪の中で、値がそのまま保たれる。
ねこ博士
そう。出力を入力へ戻すことをフィードバックと呼ぶ。輪にすると、入力が無くても値が残る。回路が「覚える」ことの正体は、これなんだ。
うさ美
でも、その輪は一度入れた値をずっと回すだけで、新しい値を書き込めませんよね。
ねこ博士
そこで、前のステージのマルチプレクサを使う。入力は、書き込みたい値 D と、書き込み許可 WE（Write Enable）。WE＝1 なら D を選び、WE＝0 なら自分の出力 Q を選んで、その結果を Q にする。
うさ美
WE＝1 のあいだは Q が D と同じになる。WE を 0 に戻すと、マルチプレクサは自分の出力 Q を選び続けるので、輪になって、最後の値が残る。そのあと D をいくら変えても、Q は変わらない。
Q（新） ＝ WE が 1 なら D、WE が 0 なら Q（いまの値） WE＝1：書き込み（Q が D に合わせて変わる）／ WE＝0：保持（輪になって値が残る）
ねこ博士
この1ビットを覚える回路をラッチ（掛け金、という意味）と呼ぶ。実際の回路では、マルチプレクサを使わずに、NAND を2つたすき掛けにつないで輪を作ることが多いけれど、「出力を戻して輪にする」という考え方は同じだ。
うさ美
ラッチを8個並べたら、8ビット、つまり1バイトを覚えられますね。
ねこ博士
そう。数を入れておく箱として CPU の中に置かれたものをレジスタと呼ぶ。64ビットの CPU なら、64個並べたレジスタを何十個も持っている。それよりずっとたくさんの値を覚えておくメモリは、1バイトずつの箱に番地という通し番号を付けて、何十億個も並べたものだ（メモリは、もっと小さく作れる別の仕組みで覚えているけれど、番地で箱を選ぶ考え方は同じ）。
ねこ博士
もう1つ大事な部品がある。足し算回路に新しい数を入れても、答えが出るまでには、ほんの少し時間がかかる。STAGE7 の繰り上がりの手渡しを思い出してごらん。
うさ美
繰り上がりが右から順に伝わるので、途中では、まだ正しくない答えが出ている時間がありますね。その途中の答えをレジスタに書き込んでしまったら困ります。
ねこ博士
そう。そこで CPU 全体に、一定の間隔で 0 と 1 を繰り返す合図を配る。これをクロックと呼ぶ。レジスタは、クロックが 0 から 1 に切り替わる瞬間にだけ値を取り込むように作る（この作りのものをフリップフロップと呼ぶ）。合図と合図の間に計算が落ち着くようにしておけば、レジスタはいつも正しい答えだけを受け取る。
うさ美
合図の間隔が短いほど、速く計算できる。……スマホの説明で「3GHz」と書いてあるのは、これですか？
ねこ博士
そう。GHz（ギガヘルツ）は1秒間に10億回。3GHz なら、1秒に30億回の合図だ。1回の合図は、光でも10センチしか進めないくらいの短い時間なんだよ。
ねこ博士
では、部品を全部そろえて、CPU がプログラムを動かす様子を見よう。メモリには、命令とデータが同じように番地付きで入っている。CPU は、次に実行する命令の番地を覚えておく専用のレジスタを持っていて、これをプログラムカウンタ（PC）と呼ぶ。CPU がすることは、次の3つの繰り返しだけなんだ。
① 取り出し：PC が指す番地から命令を読み出す。PC を1つ進める ② 解読：命令の0と1の並びを読み、「どの計算か」「どの番地か」を表す信号に分ける（演算の種類は ALU のマルチプレクサへ） ③ 実行：ALU で計算し、結果をレジスタやメモリに書き込む
うさ美
命令も、メモリの中では0と1の並びなんですね。「LOAD」とか「ADD」も、数で表してある。
ねこ博士
そう。命令ごとに番号が決まっていて、たとえば「ADD」は 0010 のように表される。その番号の部分を、②の解読でマルチプレクサの選択信号に回せば、ALU が足し算を選ぶ。STAGE9 でやったことが、ここでつながるんだ。
ねこ博士
命令の中には、PC そのものを書き換えるものもある。たとえば「JZ 番地」は、ALU のゼロフラグが立っていたら、PC をその番地に書き換える命令だ（Jump if Zero の頭文字）。
うさ美
PC を前の番地に戻せば、同じ命令を何回もくり返せる。答えが 0 になったところで先へ飛べば、くり返しを抜けられる……ということですか？
ねこ博士
そう。プログラムの「もし〜なら」も「〜のあいだくり返す」も、最後はフラグを見て PC を書き換えることでできている。
うさ美
トランジスタというスイッチから始まって、ゲート、足し算、選ぶ回路、覚える回路、そして命令を順番にこなす CPU まで来ました。最初の「スイッチしか無いのに、どうして計算できるのか」の答えが、全部この中にあります。
ねこ博士
よくここまで来たね。きみのスマホの CPU も、規模こそ違うけれど、やっていることはこの「取り出し・解読・実行」のくり返しだ。旅のまとめを見ておこう。
① 数 → 0と1の並び（2進数）。マイナスは2の補数 ② スイッチ → トランジスタ（電気の力で通り道ができる）。2個で NOT（CMOS） ③ 判断 → 論理ゲート（AND・OR・NOT・XOR）。NAND だけでも全部作れる ④ 計算 → 全加算器を並べて足し算。反転＋1 で引き算 ⑤ 選ぶ → マルチプレクサ。ALU は全部計算して1つ選ぶ ⑥ 覚える → 出力を戻した輪（ラッチ）とクロック。レジスタとメモリ ⑦ 動かす → PC が指す命令を、取り出し・解読・実行でくり返す
ねこ博士
メモリの中で番地がどう使われるのか、プログラムの中の変数がメモリのどこに置かれるのかは、『メモリのしくみクエスト』で続きを話そう。

確認クイズ

Q1. 「組み合わせ回路」と「覚える回路」の違いは？

正解！ 組み合わせ回路の出力はそのときの入力だけで決まる。輪にすると、値が回り続けて残る。

Q2. レジスタがクロックの切り替わる瞬間にだけ値を取り込む理由は？

正解！ 足し算などは答えが落ち着くまで少し時間がかかる。合図と合図の間に落ち着かせ、合図の瞬間だけ取り込めば、正しい答えだけが残る。

Q3. CPU がプログラムを動かすときに、くり返していることは？

正解！ PC が指す命令を取り出し、何をするか解読し、ALU などで実行する。PC を書き換える命令（ジャンプ）で、くり返しや条件分岐ができる。
