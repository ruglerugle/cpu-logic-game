桁あふれとマイナスの数

2の補数で引き算
🎯 ミッション
桁あふれと2の補数のしくみを説明できるようになろう。「反転スイッチ」と「2ビットの足し算・引き算回路」の2つの課題を解き、確認クイズに全問正解すれば合格。
未達成
ねこ博士
前のステージの2ビットの足し算では、答えのために3ビット用意した。でも CPU の中では、数を入れる場所のビット数は決まっている。たとえば4ビットの場所しかないのに、1111（15）に 0001（1）を足したらどうなるかな。
うさ美
筆算すると、全部の桁で繰り上がって 10000 になります。でも4ビットしか入らないなら、一番上の 1 は入る場所がなくて、残るのは 0000。15＋1 が 0 になってしまう。
ねこ博士
そう。入りきらなかった繰り上がりがこぼれ落ちることを桁あふれ（オーバーフロー）と呼ぶ。自転車や車の走行距離のメーターを見たことがあるかな。99999 km の次は？
うさ美
00000 に戻ります。それと同じですね。
ねこ博士
時計の針のように、ぐるっと回って元に戻る。4ビットの数は 0000 から 1111 の16個が輪になって並んでいる、と考えるといい。
ねこ博士
ここで逆向きを考えよう。メーターが 0000 のとき、1 戻したら何が表示される？
うさ美
輪を逆に回るから、1111 です。……あれ、0 から 1 引いたら −1 のはずなのに、1111 が出てくる。
ねこ博士
そこが今日の話の入り口なんだ。1111 に 1 を足すと？
うさ美
0000 に戻ります（桁あふれして）。「1 を足すと 0 になる数」は、ふつうの数なら −1 です。
ねこ博士
そう。4ビットの世界では、1111 を「−1」として扱っても、足し算の結果はつじつまが合う。同じように 1110 は −2、1101 は −3……と、0 から逆向きに数えた数をマイナスの数として使う。16個の並びのうち、半分の 0000〜0111 を 0〜7、残りの 1000〜1111 を −8〜−1 に割り当てるんだ。
0000〜0111 → 0, 1, 2, …, 7 1000〜1111 → −8, −7, …, −2, −1 一番左のビットが 1 ならマイナス、0 ならプラス（または0）
うさ美
同じ 1111 を、15 と読むか −1 と読むかは、どうやって決めるんですか？
ねこ博士
回路は決めない。どちらで読んでも、足し算の回路は同じ0と1の並びを出すからね。プログラムを書く人が「この場所の数はマイナスもあり得る」と宣言して、読み方を決めている。それが、同じ回路で両方を扱える便利なところなんだ。
ねこ博士
では、ある数 x のマイナス −x を、x からどうやって作るかを考えよう。手がかりとして、x と、x の全ビットを反転した NOT x を足してごらん。たとえば x＝0101 なら。
うさ美
0101 の反転は 1010。足すと、どの桁も 0＋1 か 1＋0 だから繰り上がりなしで 1111。……どんな x でも、各桁が「0 と 1」の組になるから、必ず 1111 になりますね。
ねこ博士
1111 は何だった？
うさ美
−1 です。だから x ＋ NOT x ＝ −1。両辺に 1 を足すと x ＋ (NOT x ＋ 1) ＝ 0。つまり NOT x ＋ 1 が −x になっている、ということですか？
ねこ博士
その通り。「全ビットを反転して 1 を足す」と、マイナスの数が作れる。この表し方を2の補数と呼ぶ。
x ＋ NOT x ＝ 1111 ＝ −1　（各桁が 0＋1 なので繰り上がりがない） → x ＋ ( NOT x ＋ 1 ) ＝ 0　→　−x ＝ NOT x ＋ 1 例：3 ＝ 0011 → 反転 1100 → ＋1 → 1101 ＝ −3
うさ美
それなら、引き算 A − B は A ＋ (−B) だから、A ＋ NOT B ＋ 1。足し算の回路で引き算もできる、ということですか？
ねこ博士
そう。引き算専用の回路を別に作らなくていい。必要なのは、B を反転する部品と、「＋1」の部品だけだ。しかも、どちらにもうまい手がある。まず反転。XOR の表をもう一度見てみよう。片方の入力を「切り替え信号 SUB」と考えて、SUB＝0 と SUB＝1 で分けて読んでごらん。
うさ美
SUB＝0 のときは、B XOR 0 で B がそのまま出る。SUB＝1 のときは、B XOR 1 で B の反対が出る。XOR は、SUB で「そのまま」と「反転」を切り替えるスイッチになるんですね。
ねこ博士
次に「＋1」。足し算回路の一番右の桁は、繰り上がりの入り口 Cin が空いているね。
うさ美
そこに SUB をつなげば、引き算のときだけ 1 が足される。B の各ビットは XOR で SUB と合わせて反転、一番右の桁の Cin にも SUB。これで SUB＝0 なら A＋B、SUB＝1 なら A＋NOT B＋1＝A−B。
各桁：b′ ＝ B XOR SUB　（SUB＝1 のとき反転） 一番右の桁の Cin ＝ SUB　（SUB＝1 のとき ＋1） 結果 ＝ A ＋ b′ ＋ SUB　→ SUB＝0 で A＋B、SUB＝1 で A−B
うさ美
2ビットで 01 − 10 を計算すると、1 − 2 で −1 だから 11 になるはず。2ビットのマイナスは 10 が −2、11 が −1 だから、合っています。
ねこ博士
最後に、マイナスの数を使うときの桁あふれにも注意しておこう。4ビットで 0111（7）に 1 を足すと？
うさ美
1000 です。……でもマイナスありの読み方だと、1000 は −8。7＋1 が −8 になってしまいました。
ねこ博士
プラスの一番大きい数を超えると、マイナスの一番小さい数に回り込む。だから CPU は、計算のたびに「いまの計算で桁あふれが起きたか」をフラグ（旗）と呼ぶ1ビットの印に記録して、プログラムが確かめられるようにしている。実際に問題になった例もある。多くのコンピュータは、1970年1月1日からの秒数を、マイナスありの32ビットで数えてきた。32ビットのプラスの最大は約21億秒で、それを超えるのが 2038年1月19日。そこで日付が1901年に回り込んでしまうので、「2038年問題」と呼ばれて、64ビットへの切り替えが進められている。
うさ美
32ビットでも足りなくなるんですね。桁の数を決めることが、そのまま使える数の範囲を決めている。
ねこ博士
そう。次のステージでは、足し算・引き算・AND・OR……といういくつもの計算を、1つの部品にまとめる。CPU の計算係、ALU だ。

確認クイズ

Q1. 4ビットで 1111 に 0001 を足すと、残る4ビットは？

正解！ 筆算の答えは 10000 だが、5桁目は入る場所がなくこぼれる（桁あふれ）。残る4ビットは 0000。

Q2. 2の補数で、4ビットの −5 を作ると？

正解！ 5＝0101 → 全ビット反転 1010 → 1 を足して 1011。確かめ：0101＋1011＝10000 で、4ビットは 0000。

Q3. 引き算 A − B を足し算回路で計算できる理由は？

正解！ −B は NOT B ＋ 1（2の補数）。SUB 信号で B を XOR して反転し、同じ SUB を Cin に入れれば、同じ足し算回路が引き算もこなす。
